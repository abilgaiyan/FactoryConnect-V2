# G2 runtime mTLS and protected machine reads

This increment supplies a real TLS transport verifier and an exact assigned-machine SQL read boundary. It does not register a production listener, wire an HTTP runtime endpoint, record configuration acknowledgements, publish an active roster or change production credentials. Server certificate/private-key provisioning, issuing CA/CRL infrastructure and deployment/network policy remain explicit operational inputs.

## Transport possession and CA status

`RuntimeMtlsServer` owns `SslStream` negotiation on a server-provided transport, using an explicitly provisioned server certificate, pinned public CA and one explicit HTTP(S) CRL URI. TLS 1.2/1.3 and encryption are required; renegotiation and TLS session resumption are disabled. A missing certificate is rejected in the validation callback and the completed stream must be authenticated, mutual, server-side, signed and encrypted. Setting `ClientCertificateRequired` alone is insufficient. No caller certificate header, asserted runtime ID, verifier flag or serialized channel receipt is accepted.

The initial direct-root certificate profile from registration is checked again. Online chain validation uses only the exact configured CA, client-auth EKU, no verification-flag overrides, no issuer downloads and revocation checking excluding the explicitly pinned root. It never invokes the offline registration `NoCheck` path. Revoked, expired, unknown or unavailable revocation status fails closed. The leaf must have exactly the configured encoded CRL distribution point and no AIA extension; additional issuer/OCSP sources are not silently accepted. Retrieval has a one-second platform URL budget, and the overall handshake has a ten-second cancellation budget.

The chain engine can reuse a still-valid signed CRL from its platform cache. An unreachable endpoint therefore denies when no usable status exists, not necessarily while a valid cached CRL remains available. External CA publication/cache latency is distinct from immediate SQL credential/principal revocation. Root compromise/withdrawal needs operator trust-policy replacement and affected credential revocation; no global CA incident command is invented here. Platform redirect, cache and outbound network behavior require deployment qualification on the actual OS/PKI. These checks were executed with .NET 10 on Linux in disposable CI, not on a factory server.

`RuntimeMtlsChannel` is sealed, nonserializable and has no public constructor. Only the owned successful handshake mints it. Its byte I/O methods are transport primitives, not machine authorization; a host must invoke the protected SQL boundary for each bounded request/page. Private keys stay in externally managed certificate stores/vaults or fixture memory. Raw certificates, identities, SQL, headers and payloads are absent from trace metadata.

## Current SQL authority

`ReadRuntimeMachineAsync` accepts the verified channel and exact site/machine, never a human session token. It refreshes certificate/CA validation before opening a SQL transaction. It then takes installation security shared → common machine shared, captures SQL time and rejects a CA verdict aged more than five seconds during connection/gate waits. Certificate, credential, anchor and assignment validity are checked again at that SQL cut. No network/CA validation runs while its SQL gates are held.

An indexed exact lookup resolves the peer certificate SHA-256 plus byte-for-byte DER and configured anchor SHA-256 against immutable registration. Fixed binary hash parameters avoid implicit hash-type conversions. The registered generation must still be the current credential, match retained public-key material and belong to an unrevoked `R` principal. Its current assignment must match the exact machine/site, be effective, and not be revoked; retired machines/sites reject. The handler receives only SQL-derived runtime, assignment and credential identities/generations and uses the same connection/transaction under the held gates. Handlers are trusted server code and must be bounded, cancellable reads; arbitrary SQL or unbounded streams must not be exposed through this API. Unavailable SQL is an error, never an authenticated empty set.

A handshake or long-lived channel creates no authorization lease. Each protected read rechecks current assignment and credential authority. Certificate rotation invalidates the old channel's application access; a new handshake with the exact newly registered certificate resolves the new credential generation without rewriting assignment generation. This does not transfer any configuration acknowledgement. Disposed channels reject reuse. Authentication does not establish runtime connectivity, activation or metrics availability.

Read-versus-revocation follows the existing common gate contract: a read holding shared gates may finish before a later revocation obtains exclusive authority; a read queued behind a revocation sees the committed invalidation and denies. Its response may arrive later due to transport latency; already returned/in-flight data is not erased. The immutable authority record passed to a handler is metadata for that protected cut, not a reusable token for future operations.

## Executable evidence and remaining work

Non-SQL transport fixtures perform real TLS 1.2 and TLS 1.3 handshakes, encrypted byte exchange and signed CRL delivery over loopback HTTP. They reject absent/private-key-less client certificates, wrong pinned CA, a mismatched encoded CRL URI, a revoked leaf, expired CRL, missing CRL and timeout. Keys, CAs, server/client certificates, CRL services and sockets are ephemeral and disposed. Each negative CA-status fixture has its own CA to avoid borrowing another fixture's cached CRL.

Disposable SQL acceptance uses actual signed bootstrap, human/grant/certificate enrollment and runtime assignment commands. It proves unregistered/unassigned denial, exact DER rather than public-key-only matching, an independently injected certificate-to-retained-key integrity conflict, authoritative scope, retirement/seal handling, current assignment replacement, bounded-verdict aging after an observed machine wait, both actual read/revocation commit orders, old-channel invalidation after rotation and independently preserved assignment generation. Trace sampling proves CA stages occur outside SQL transactions. Warm whole-read smoke checks include CA validation and SQL, with a full-path SQL roundtrip ceiling; they are not production capacity or p99 claims. Existing 100-machine submission, activation, assignment and inventory performance gates still run.

No schema migration is needed. Remaining work includes generation-bound activation acknowledgement, reviewed runtime HTTP composition, operational CA/revocation/cache/outage qualification and actual deployment acceptance. The default application host remains unchanged.
