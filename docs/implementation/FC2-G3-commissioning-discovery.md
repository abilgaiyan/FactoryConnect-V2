# Authenticated commissioning discovery

Backend implementation on `fc2/commissioning-discovery`; SQL qualification and measured results are tracked in its pull request. No HTTP endpoint, listener, machine write, migration or production deployment is introduced.

`ReadCommissioningSiteAsync` requires a current human session with site-wide `commissioning.read`. A machine-scoped grant cannot expose a whole site. `configuration.read`, administration, editing, review and activation do not imply this permission; discovery grants no active-roster permission or runtime authority. The result is fully materialized under the shared installation security gate, with server-generated SQL UTC evaluation time and ordering epoch. The epoch is not a cross-authority publication identity.

Every selected machine appears, including unassigned, assigned-but-unenabled and not-yet-acknowledged machines. Discovery follows the latest activation-request head independently of the last acknowledgement. It returns the immutable requested activation/revision/hash/review, distinct runtime/assignment/credential/operating generations and explicit effective interval, alongside current assignment/credential/operating generations, operating status and last acknowledgement identity. `AcknowledgesRequestedActivation` identifies an exact historical relationship; it is not connectivity or current active eligibility.

States are explicit: `not-requested`, `pending`, `scheduled`, `acknowledged`, `blocked` or `unavailable`. Revoked, expired, retired, suspended, generation-mismatched and known policy-ineligible requests remain visible as blocked. Scheduled policy revocations and runtime expiry are checked at the later of SQL now and requested first use. A pending request cannot silently adopt a new assignment, credential or enable generation. There is no timestamp-based or historical-head fallback. Missing current pointers with retained history make the whole discovery result unavailable. Consumers must not publish a partial complete result from that cut.

Configured capability intent comes only from a hash-verified approved canonical package, with normalized timezone/schedule/break, production-line and package-interval pins compared to those bytes. Intent does not establish metric inputs, production or connectivity. Current database credential/certificate checks do not substitute for fresh online CA validation during mTLS. Discovery neither signs in nor authenticates a runtime and cannot acknowledge an activation.

The SQL batch bounds a complete site at 100 machines, canonical bytes at 1 MiB per package and 8 MiB across distinct referenced packages. Each package is transferred once per cut; no per-machine SQL loop, raw observation retrieval or reconstruction of historical revisions is introduced. Unknown sites and oversized cuts fail explicitly instead of becoming complete empty/truncated views. Master rows use transaction-held SQL read locks; supported authority writers take installation security Exclusive before policy/machine resources. Discovery takes no additional application lock and requires no upgrades. Privileged maintenance writes outside that contract are not concurrent authority producers.

Acceptance uses real bootstrap, scoped grants, certificate enrollment, assignment, independent enable/resume, activation and mTLS acknowledgement workflows. It covers permission separation, pre-enable/pre-ack discovery, exact pins and capability intent, scheduled replacement versus last acknowledgement, policy first-use revocation, canonical corruption denial, missing-head integrity, withdrawal/read commit orders via observed SQL waits, suspension/resume, current grant revocation and overflow. The 100-machine fixture uses explicitly labelled upstream enable facts for additional capacity machines, then real assignment/activation producers. It measures 128 complete cuts at concurrency one and eight, bounded pool size and full-transaction roundtrips. Budgets are <=12 TDS roundtrips, p95<2s and p99<5s in disposable CI, not production or HTTP capacity. `artifacts/performance/commissioning-discovery.json` is uploaded by CI. No isolated logical-read totals are claimed; PR #29 showed pooled-session deltas are unreliable.
