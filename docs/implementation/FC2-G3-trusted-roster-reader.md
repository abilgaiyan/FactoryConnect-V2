# Trusted site eligibility reader

Backend-only reader on `fc2/trusted-roster-eligibility`. Qualification results are tracked in the pull request. No HTTP roster, commissioning discovery, runtime listener or production deployment is introduced.

`SqlSecurityAuthority.ReadTrustedSiteRosterAsync` requires a current human session and site-wide `configuration.read`. Administration, activation and machine-level grants do not implicitly grant site-wide visibility. Callers cannot provide proof flags or an evaluation instant. The reader obtains SQL UTC time and the security ordering epoch after acquiring the shared installation gate; the epoch is not a cross-authority publication revision.

A complete site is bounded at 100 machines, 1 MiB per package and 8 MiB of distinct canonical package bytes. The query fetches at most 101 machine IDs before rejecting overflow, and transfers each referenced canonical package once. An unknown site, oversized cut or SQL/authorization failure throws; it cannot become healthy empty or a truncated eligible set. No per-machine SQL verification loop, raw observation scan or timeout increase is introduced.

The result contains every selected machine's eligibility outcome and an overall status. `healthy-empty` requires a complete successful authorized source cut and no eligible or unavailable rows. Any missing authoritative head with retained history, or incomplete authority for an acknowledged configuration, makes the overall result `unavailable`; consumers must not publish a partial eligible set from that result. Retired, suspended, unknown/uncommissioned, ineffective, revoked or generation-mismatched configurations are explicitly excluded.

The last acknowledged head is separate from the latest pending request head. A pending replacement retains the last acknowledgement only while that exact historical activation's approval, intent, runtime/assignment/credential/operating generations, certificate interval, policies and effective interval remain eligible. No scan chooses a fallback from earlier acknowledgement history. A removed head with retained history is an integrity failure, not a new uncommissioned machine. Resume, assignment replacement and credential rotation cannot revive an old acknowledgement.

One set-based query joins the authoritative current heads to exact immutable acknowledgement pins, approval, package/machine assignment, runtime certificate/key/credential/assignment and operating transition. It checks timezone/schedule/break revocations directly using indexed exact revision/hash probes. Package hashes and selected normalized policy/line/interval pins are independently compared with immutable canonical bytes before an eligible row is returned. Configured capability intent comes from those bytes and is descriptive only: it proves neither available metric inputs, live connectivity nor production.

The shared installation security gate is held through authorization, SQL reads, canonical verification, materialization and commit. All supported authority writers take that gate exclusively before policy/machine resources, so this reader requires no additional application lock or lock upgrade. Master site/machine/line rows use transaction-held SQL read locks. Out-of-band privileged database edits are maintenance actions, not a supported concurrent authority producer. Certificate checks here concern stored bindings/SQL revocation and validity intervals; fresh online CA revocation evidence remains an mTLS transport responsibility.

Acceptance uses real bootstrap, human grants, runtime certificate enrollment, runtime assignment, activation and mTLS acknowledgement producers. Additional machines in the capacity fixture use the explicitly labelled upstream operational-enable fixture; the single-machine lifecycle uses real independent enable/resume approval. Tests cover exact authority, complete empty/incomplete cuts, last-ack retention, retirement, direct policy/approval revocation, operating-generation fencing, current grant denial, both writer/read commit orders using observed SQL waits, and 100 machines/eight concurrent readers. The full transaction budget is 12 TDS roundtrips and five seconds in a disposable CI fixture. These gates do not establish production capacity.

The capacity fixture additionally measures 128 warm complete site cuts at concurrency one and eight, recording p95/p99, full-transaction roundtrips, gate wait, bounded pool size and observed pooled-session logical-read counter deltas in `artifacts/performance/trusted-roster.json`. Counter deltas include authorization and temp-table work; they are not query-plan attribution, and are explicitly unavailable on counter decrease. CI uploads the artifact alongside inventory evidence.
